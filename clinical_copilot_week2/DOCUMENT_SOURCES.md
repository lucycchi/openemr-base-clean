# Document fixture sources

Rule. The PRD asks for "real-world clinical documents" and "the messy
inputs clinicians actually receive" while requiring "only demo or synthetic
data" (Week 2 PRD, pp. 2-3). We resolve that by making the documents
realistic and the patients synthetic: layouts are real lab and health-system
forms; lab values, medication lists and condition histories are drawn from
the public-domain NHANES survey so abnormal patterns are realistic; and every
patient, name, date and contact detail is invented and tied to a seed
patient. No dataset of identifiable or DUA-restricted patient records
(MIMIC, eICU, n2c2) is used, whatever its access terms, because a fixture
derived from it would be real patient data in a repository graders clone.
Free text is never copied from any source verbatim. Every file under this
directory has a row here with its origin, its terms, and what was changed.
Files not listed here are generated by `generate.py` (synthetic).

Status legend: `candidate` (found, not vetted), `vetted` (checked by Lucy
Chi: fictional data, terms allow use), `chosen` (a fixture is built from it),
`rejected` (with the reason).

## Decision (2026-09-22): NHANES values, invented identities, no Synthea

Ranking on lab rows (value, unit, range, flag, date), chart data (meds,
allergies, problems, family history, demographics) and PRD compliance:
NHANES first (realistic values and histories, public domain, no PHI),
Synthea second (compliant but generated: textbook values, narrow analytes),
MTSamples for wording only. MIMIC would rank first on realism and is out on
the PRD rule.

NHANES stands alone as the source of clinical values. Nothing synthetic is
spliced behind it; what it lacks is invented per fixture, not generated:

| Field | Comes from |
|---|---|
| Lab values, units, fasting status | NHANES respondent (one `SEQN` per fixture patient) |
| Med list, with indication | NHANES `RXQ_RX` + `RXQ_DRUG` (ICD-10 reason) |
| Problem list, ages at diagnosis, smoking/alcohol, BMI, BP | NHANES `MCQ`/`DIQ`/`BPQ`/`KIQ`/`SMQ`/`ALQ`/`BMX`/`BPXO` |
| Family history | NHANES `MCQ300*` where the cycle has it; else invented |
| Reference ranges | The report template as printed |
| Abnormal flags | Computed: value vs the template's range; recorded in `truth.json` |
| Collection date, report date, lab name, ordering provider | Invented; dates tied to the seed patient's encounters |
| Name, DOB, phone, address | The seed patient (Week 1 seed set); the NHANES respondent's sex and age band match it |
| Allergies, chief concern, form date | Invented (NHANES has none) |
| Prior chart panel | The same NHANES panel seeded as `procedure_result` rows dated before the visit |
| Second and third reports (`lab_delta`, trend widget) | The first report with recorded perturbations, so the expected delta is exact |

Gathering: join `DEMO ⋈ CBC ⋈ BIOPRO ⋈ TCHOL ⋈ HDL ⋈ GHB ⋈ RXQ_RX ⋈ MCQ ⋈
BPQ ⋈ DIQ` on `SEQN`; filter to the seed patient's sex and age band and to the
profile the case needs (for example diabetic on metformin with A1c > 8; statin
with LDL in range; CKD with creatinine > 1.5; a healthy control); pick one
respondent per fixture patient (5-8 in total) and record the `SEQN` and cycle
on the fixture row. A respondent's full row is never committed; only the
values that appear on the rendered document and in the seeded chart.

## Filled forms and scanned documents

No public corpus of filled patient intake forms is known. Kaggle sets titled
"medical form OCR" or "lab report OCR" are small and of unclear provenance,
rejected for the same reason as the Scribd copies. FUNSD
(https://guillaumejaume.github.io/FUNSD/) and RVL-CDIP are scanned-form
datasets with layout ground truth but non-medical; only useful for
sanity-checking OCR and anchoring on messy real scans before the hand-filled
intake. The route is therefore: an NHANES respondent → answers drawn from their
meds, conditions and social history (reworded) plus invented allergies and
chief concern → typed into a blank form above → one copy printed,
hand-filled and scanned.

## How a chosen source becomes a fixture

1. Fill the form (or edit the sample) with invented answers tied to a seed
   patient so the chart-vs-document cases are real (for example, write
   "stopped lisinopril" for a patient whose chart still lists it).
2. Save as PDF (text layer). For at least one intake form, also print it,
   fill it by hand, and scan or photograph it to PDF: handwriting is the
   honest stress test.
3. Write `<name>.truth.json` (every clinical field with page and row) and,
   for anchor-mode cases, record `<name>.model.json` once from the real
   model.
4. Add the row above with status `chosen` and the changes made.
