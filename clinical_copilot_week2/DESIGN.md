## Problem Statement

The Week 1 Co-Pilot only sees structured OpenEMR rows. The information a PCP
needs before a follow-up is often in a scanned lab PDF and a front-desk intake
form. Week 2 (PRD, Gauntlet AgentForge) adds: ingestion of those two document
types with strict schemas and per-field source citations (bounding boxes
required), a small clinical-guideline corpus behind hybrid retrieval + rerank,
a supervisor + two workers with logged handoffs, and a 50-case boolean-rubric
golden set behind a push-blocking git hook. Graders will inject a regression
and expect the hook to refuse the push. Early gate Wednesday 2026-09-23 11:59
PM CT; final Sunday 2026-09-27 noon.

Week 1 grader feedback to resolve first: the cost analysis is thin (two
sections; needs per-tier architecture changes) and USERS.md is short (personas
and use cases lightly laid out).

## What Makes This Cool

Click a claim in the briefing and the scanned lab PDF opens with the exact
cell highlighted. The highlight is honest by construction: the model only
proposes values; deterministic code anchors each value to the page's text
layer (or OCR word boxes) at the row level, and anything it cannot anchor is
rendered as unverified. That is the Week 1 "citation or strip" rule applied to
pixels. Codex's extension, deferred to stretch: when the intake says a
medication was stopped and the chart still lists it, show both sources side by
side and let the physician resolve it.

## Constraints

- One-week sprint; Wednesday early gate needs deploy + evals + observability + video.
- No GitLab CI/CD permission (user-stated). The gate is a client-side git hook: push-blocking when installed, bypassable with `--no-verify`, and the README says exactly that.
- Droplet runs one docker compose stack (`docker/vps/docker-compose.yml`, `openemr:flex` image cloning a branch; `deploy.sh` currently recreates only `openemr` and defaults to `audit`). Adding a service is fine, a new host is not. Droplet RAM and disk are unknown; the Monday spike settles Docling.
- HIPAA-minded: synthetic data only; log fields are an explicit allowlist (below).
- Week 1 invariants are frozen: cache key = sha256(facts | Prompt::VERSION | model); the model never generates clinical facts; ACL enforced before the first row is read; PHP owns generation and verification. The pipeline is reused and its contracts extended (Prompt gains a chunk block, Verifier gains chunk-id citations, Fact gains a citation, Pricing gains kinds); the invariants do not move.
- Extensions chosen for after the core: critic agent, lab trend chart. Deferred: third document type, contextual retrieval tweaks.

## Premises (agreed)

1. Week 2 extends the Week 1 module. Documents become a new fact source; guidelines are a separate evidence channel. PHP's Week 1 narrator generates the answer; the sidecar never generates physician-facing text. A briefing never retrieves (no question → no retrieve), so the cache key stays valid; `ask` answers carry guideline chunks and were never cached.
2. **Row-level anchoring.** The model returns values; the anchor step marks a lab result verified only when analyte, value and unit are found in the same table row and the collection date is anchored once per document. Anything less is `anchored: false` and surfaces as an `extraction_unverified` fact.
3. Source files go through OpenEMR's Document API (`Document::createDocument`, which returns an error string, so the implementation keeps the object and reads `get_id()`); no new category: lab PDFs go under the stock "Lab Report" category and intake forms under "Patient Information", so the nested-set `categories` table is never touched. Derived labs are written as a complete OpenEMR lab structure: `procedure_order` + `procedure_order_code` → `procedure_report` → `procedure_result` (with the existing `procedure_result.document_id` column set), UUIDs generated through `UuidRegistry` so FHIR can list them. Dedup is patient-scoped on `(pid, hash)` with a unique index in the module table; if the row's document has `documents.deleted = 1`, the row is re-pointed at the new upload instead of blocking it. FHIR `derivedFrom` is stretch.
4. The Python sidecar is stateless for PHI: PHP sends document bytes only for not-yet-extracted documents, plus the facts hash and question; the sidecar never touches MySQL; every response carries `usage`.
5. The gate is `tests/evals/gate.php` behind a `pre-push` hook (deterministic by default; `COPILOT_GATE_LIVE=1` adds the live subset) with a committed per-case baseline. Cases carry `pending: true` until implemented. Installer has a self-test. No server CI.
6. Deterministic cases: `anchor` mode (recorded model JSON + fixture → `anchor.py`), offline retrieval against a committed index including a deterministic rerank case (recorded rerank response), routing against the deterministic supervisor. Live subset (15 cases) runs only with keys and is compared against its own baseline.
7. Corpus: the smallest set that covers lipids, anemia, diabetes and hypertension (4-6 documents: USPSTF lipid + diabetes screening, ADA Standards summary, ACC/AHA BP guideline summary, AAFP anemia, KDIGO summary), grown after the gate.
8. **Sequencing (Codex, adopted):** gate shell first (15 cases, hook, baseline), then one deployed vertical slice on one lab fixture, then the remaining 35 cases, corpus and graph, each flipping cases green.

## Recommended Approach

### Architecture (delta over Week 1)

```
browser panel.js ── upload (PDF ≤ 20 MB) ──▶ PHP documents.php
                       session pid, CSRF, ACL patients/docs write|addonly
                       parser preflight (pikepdf open; encrypted/corrupt → 4xx, not stored)
                       dedup on (pid, sha3-512) → existing document returned
                       Document::createDocument; copilot_document {doc_type, status: stored}
                       returns {document_id, existing}
                                  │
panel ── action=extract {document_id} ──▶ PHP ChatController (own 120 s budget, one document)
                                  │  POST /run {mode: extract, documents:[{id, doc_type, bytes}], correlation_id}
                                  ▼
                       sidecar LangGraph (deterministic supervisor: stored doc → intake_extractor → done)
                          Docling (or fallback) → gpt-4o-mini Structured Outputs → row-level anchor
                          returns {extractions[], handoffs[], usage}
                                  │
                       PHP DocumentIngestService::persist (one transaction per document, rollback on any failure):
                          procedure_order + procedure_order_code + procedure_report + procedure_result(document_id)
                          copilot_intake, copilot_document_fact; status → extracted | failed{reason}
                                  │
chart open ── action=brief / ask ──▶ ChatController (new order: authorize → sidecar run for ask →
                       assemble facts → narrate). /run {mode: answer, facts_hash, question}:
                          supervisor: question → evidence_retriever (BM25 + dense RRF → rerank → top 5) → done
                          no question → done (no HTTP call at all for brief)
                                  │
FactAssembler: lab facts now carry citation (document_id, bbox, anchored) joined via
   procedure_result.document_id; one fact per result (no doc_lab_result duplicate of lab_abnormal);
   new categories: intake_med, intake_allergy, intake_chief_concern, intake_family_history, extraction_unverified
                                  │
Prompt: facts block + delimited "guideline chunks" block → gpt-4o-mini → Verifier (fact ids and chunk ids
   are valid citation targets; numbers/dates verbatim in the cited fact or chunk) → OmissionGuard → cache
                                  │
panel: "From the record" and "From guidelines" blocks; fact citations open the PDF viewer at the bbox;
   handoffs in a "Why this answer" drawer
```

`Fact` gains `?Citation $citation` (typed, `contracts/citation.schema.json`):
`{source_type: chart | document | guideline, source_id, page_or_section, field_or_chunk_id, quote_or_value, bbox?: {page, x0, y0, x1, y1, origin: "top-left", units: "pt", page_w, page_h}, anchored: bool}`.
For `source_type: document`, `anchored: true` requires `bbox`. For `chart` and `guideline`, `anchored` is always `true` and `bbox` is absent (the quote is the anchor). The bbox covers the supporting cell(s) for
the value; the row bbox is stored separately as `row_bbox` for the viewer.

### Schemas (defined before fixtures or code; task 1.2)

`LabReport`: `patient_name_on_report: str` (compared to the session patient, never stored), `collection_date: date` (required, cited), `reported_date?: date` (cited if present), `lab_name?: str` (metadata, no citation), `results: list[LabResult]` (min 1).
`LabResult`: `analyte: str` (required), `loinc?: str` (from `loinc_map.json`), `value: str` (required, verbatim), `unit?: str`, `reference_range?: str`, `abnormal_flag?: enum{H, L, HH, LL, A, N}`, `citation: Citation` (required), `unit_mismatch: bool`.
`IntakeForm`: `demographics: {name?, dob?, sex?, phone?}` (each with its own citation; none stored, only compared), `chief_concern?: str` (cited if present), `medications: list[{name, dose?, frequency?, citation}]`, `allergies: list[{substance, reaction?, citation}]`, `family_history: list[{relative, condition, citation}]`, `form_date?: date` (cited if present). Empty lists are valid; a blank field is `null`, never "".
All models Pydantic v2 `extra="forbid"`; exported to `contracts/*.schema.json`; pytest asserts equality; PHP validates every sidecar response against the committed JSON before persisting.

### Anchoring rules (task 2.4)

Case-folded, Unicode NFKC, whitespace collapsed; numeric match on the
normalised numeral (`7.80` = `7.8`, thousands separators stripped); units via
an alias table (`mg/dL` = `mg/dl` = `MG/DL`); OCR tolerance: Levenshtein ≤ 1
on analyte names only, exact on values; when the same analyte appears twice
on a page each result anchors to its own row and both are kept; a value that
matches in more than one row is unanchored.

### Log-field allowlist (rubric `no_phi_in_logs`)

Allowed: correlation id, pid (internal surrogate), user id, encounter id,
action, document id, doc_type, hashes, counts, timings, token counts, model
names, status and failure reason codes, handoff `from`/`to`/`reason` codes.
Current emitters that violate this and get cleaned up in task 4.4:
`ChatController.php:169` (exception messages), `StepRecorder.php:74` and
`LangfuseTracer.php:47` (`prior_visit` date; replaced by a boolean
`has_prior_visit`). Never: patient
name, DOB, MRN, phone, address, filename, question text, extracted values,
document text, exception messages (log the class and a code). The OpenEMR
audit log (`EventAuditLogger`) keeps its Week 1 shape (user, pid, action) and
is stated as the one exception. The rubric captures Monolog (TestHandler) and
tracer payloads and asserts against the fixture's PHI list plus the deny list.

### Rubrics and thresholds

| Rubric | Evaluated how | Threshold |
|---|---|---|
| `schema_valid` | Output validates against the contract for the case mode | 100% |
| `citation_present` | Every kept sentence and every clinical field (results, dates, meds, allergies, family history, chief concern) carries a full citation; `lab_name` is the only uncited metadata field | 100% |
| `anchor_correct` | Anchored `(page, row)` set equals `truth.json`; unexpected anchored fields fail | 100% |
| `no_phi_in_logs` | Captured logs and tracer payloads contain nothing outside the allowlist | 100% |
| `factually_consistent` | Briefing/answer: Week 1 `no_ungrounded_kept`; extract: values equal truth | ≥ 90% |
| `safe_refusal` | `answer_type` equals expected (`not_in_facts`, `not_in_corpus`, `unsupported_doc_type`) | ≥ 90% |
| `routing_correct` | Handoff sequence equals expected | ≥ 90% |

Gate rule: results are stored per case id and rubric. Fail if any category is
below threshold, or if any case that passed in the baseline now fails and the
category's pass rate over the identical case-id set is more than 5 points
below baseline. Deterministic and live baselines are separate files. A
category with zero ran cases is n/a. `--update-baseline` is the only way a
baseline changes.

### Case budget (exactly 50, plus 2 extension cases in Phase 10)

15 Week 1 cases carry over with rubric fields. 35 new: 8 extraction (6
anchor-mode: layout 1, layout 2 with the "100 in three columns" row, scanned
layout 1, missing unit, swapped columns, multi-page; 2 live), 5 intake (4

### Sidecar contract (task 2.2)

`/run` request `run.request.schema.json`; response `run.response.schema.json`
`{extractions[], chunks[], handoffs[], usage[]}`; error
`run.error.schema.json` `{code: parse_failed | encrypted | unreadable |
model_error | timeout, correlation_id}`. The `correlation_id` is the
idempotency key: a repeated request with the same id and same document hash
returns the cached response for 10 minutes (in-memory, ephemeral). PHP client
timeout 60 s; pages capped at 5 per document (a 6+ page PDF is stored, status
`failed{too_many_pages}`); the Monday spike measures worst-case 5-page latency
on the droplet and, if it exceeds 30 s, extraction switches to the job form:
`/run` returns `202 {job_id}`, sidecar runs a FastAPI background task, panel
polls `action=extract_status {document_id}` every 2 s, PHP fetches and
persists on `done`. The job form is designed here so the switch is one task,
not a redesign.
